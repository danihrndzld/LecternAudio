# AAX → M4B conversion

## Sources

The implementation is independently written against the public [FFmpeg AAX demuxer documentation](https://ffmpeg.org/ffmpeg-formats.html#Audible-AAX) and [FFmpeg command documentation](https://ffmpeg.org/ffmpeg.html). Conversion copies the audio without re-encoding, keeps the chapters, and attaches the cover. Lectern Audio doesn't use any third party key service, and no GPL conversion code is copied.

## Lectern Audio behavior

### Account-driven automation

The product flow is account sign-in → library sync → authorized download → automatic key resolution → conversion.

### Account-driven workflow

- Sign-in persists the registered device, bearer/refresh tokens, customer identity and registration cookies in Keychain. The browser remains nonpersistent; restoring the app session does not require browser cookies. Older saved sessions obtain missing identity and cookies through Amazon's authenticated profile and cookie-exchange endpoints. Failed restoration preserves the previous Keychain item and asks the user to sign in again.
- Catalogs, outputs and queue files are isolated under `Application Support/Lectern Audio/accounts/<hashed account and marketplace>/`. Signing out cancels current work and hides that account's catalog; saved audio is retained. Signed API requests use an ephemeral transport that rejects redirects. CDN requests carry no account authentication or cookies.
- **Download and Convert** requests a signed, granted AAXC license for the selected ASIN, decodes its voucher in memory and runs FFmpeg with `-audible_key` / `-audible_iv`. No raw license or key is written to disk. For locally imported AAX books present in the synced library, the signed activation endpoint supplies account-level activation data cached in Keychain.
- The queue persists metadata and state, and runs several jobs at once (Settings ▸ Advanced ▸ Simultaneous downloads, 1 by default). Interrupted work requeues on relaunch, while failed/cancelled jobs wait for **Retry**: automatic downloading after a sync never revives them, and only an explicit action resets a finished job. When the network itself is unreachable the queue holds its position with the job still queued, rather than failing every restored job in turn; **Retry**, the next successful sync or a completed job releases the hold. Downloads use disk-backed HTTP ranges and retain completed chunks; servers that ignore ranges restart the transfer without appending duplicate bytes. Partial files are scoped by a fingerprint of their content credentials. A fresh license is requested on retry/relaunch.
- Output is validated before registration. Existing output left by an interruption is checked before adoption, never overwritten. The encrypted download under `sources/` is deleted once the converted output has been recorded, since it is re-downloadable, useless without a fresh license and about the size of the finished book; a failed or cancelled job keeps its partial download so **Retry** can resume. Embedded chapters/artwork are retained, with license chapters and the library cover used when available.
- **Downloads** exposes progress, cancellation, retry and **Download Missing Books**. Automatic downloading after future syncs is opt-in to avoid unexpectedly transferring an entire library. The inspector, context menu and Conversion menu expose per-book/selection actions.

AAX activation data belongs to the account; AAXC vouchers are content-specific. Offline tests cover registration compatibility, cookie/profile restoration, a voucher known-answer vector generated with OpenSSL, signed requests, malformed/denied licenses, range validation, cancellation, restart and queue restoration. Live-account download/conversion has not been exercised in this change; server-side policy or format differences may still require follow-up. A revoked license is reported rather than bypassed. Split-only titles and non-AAC formats are not implemented.

Protocol references: the MIT-licensed [Audible authentication implementation](https://github.com/mkb79/Audible/blob/master/src/audible/auth.py), [activation endpoint](https://github.com/mkb79/Audible/blob/master/src/audible/activation_bytes.py), [voucher decoding](https://github.com/mkb79/Audible/blob/master/src/audible/aescipher.py), [audible-cli license requests](https://github.com/mkb79/audible-cli/blob/master/src/audible_cli/models.py), and [FFmpeg AAXC input options](https://ffmpeg.org/pipermail/ffmpeg-cvslog/2020-November/125026.html). Amazon profile/deregistration calls use `x-amz-access-token`, matching the current reference rather than its legacy bearer-header convention.

Account-workflow verification: 46 core tests passed locally, including the optional public encrypted-AAX conversion and real FFmpeg remux tests. The signed app built successfully; a downloads-sheet snapshot was rendered with synthetic metadata and Keychain loading disabled. These checks do not prove a live AAXC account download, actual token renewal, or interactive Keychain prompts. No user session secret was read by the development tools; only the presence of the Keychain item was checked.

### Implemented local-file workflow

1. Select a book with an AAX file and choose **Convert to M4B…** in the inspector, context menu or Conversion menu.
2. Lectern Audio uses its bundled FFmpeg helper. `scripts/build-ffmpeg.sh` downloads the checksum-pinned, unmodified FFmpeg 8.0 archive from ffmpeg.org and compiles only the needed formats/codecs, with GPL/nonfree components disabled. It builds the Xcode target architectures and caches them under `build/ffmpeg-8.0`. The app bundles the source archive, LGPL license and build script under `Contents/Resources/FFmpeg`.
3. Enter the eight hexadecimal activation characters for the account that owns the file. Optional persistence uses Keychain, keyed by book ID. Lectern Audio does not obtain keys automatically. The key is passed to FFmpeg in process arguments as required by its CLI, so it is visible to sufficiently privileged process inspection while conversion runs. It is never written to conversion metadata or application logs. FFmpeg stderr is discarded to prevent accidental key disclosure; failures therefore show a generic actionable message.
4. Each download job has its own converter actor and manual conversions share another; all of them pass through one limiter, so Simultaneous conversions bounds FFmpeg processes independently of how many downloads run. A job that has finished downloading waits for a conversion slot while still holding its download slot, so setting conversions far below downloads leaves download slots idle. The converter passes arguments directly to `Process`, without a shell. Audio is copied; a local library cover is preferred, with optional embedded video artwork as fallback. Imported title, author, narrator, genre and summary override corresponding source tags; `ausr` is removed and audiobook media type is set. Valid library chapters override embedded chapters. Missing, overlapping or invalid chapter lists fall back to the source.
5. Progress comes from FFmpeg's machine-readable `out_time_us`, relative to the imported duration. Cancellation terminates the process, escalates after a short grace period, and removes staging files. Missing/incorrect duration affects progress display, not conversion.
6. Output is staged in a unique directory beside the destination. On successful FFmpeg exit, Lectern Audio checks nonempty output and decodes the first second without any key. This is an initial playability check, not a complete decode verification of an entire audiobook. It then moves the result to `books/Earmark/<source name>.m4b`, refusing to replace existing files. The original AAX is kept, unless **Move AAX files to the Trash after converting them** is on in Settings ▸ General. Then, for a book in the signed-in Audible account converted with the account's key (never with typed activation bytes), the AAX goes to the Trash after the output has been registered and its full duration, read with AVFoundation, is within 90 seconds of the book's length. An unknown or different duration, or a failed move, keeps the AAX and is logged. OpenAudible downloaded these files and still lists them in `books.json`, so it shows them as missing.
7. `earmark-conversions.json` maps book IDs to converted file paths. Loading the library merges existing outputs into the book list, enabling playback and MP3 export. OpenAudible's `books.json` is never rewritten. If recording fails, the newly converted output is removed so a retry can proceed.

The manual local-import path accepts `.aax`; AAXC is handled by the account download workflow. Existing local-import output collisions are reported rather than overwritten; rename or move the existing output before retrying.

## Verification

```sh
swift test --package-path Packages/AudibleCore
LECTERN_TEST_FFMPEG=/opt/homebrew/bin/ffmpeg swift test --package-path Packages/AudibleCore
xcodegen generate
xcodebuild -scheme LecternAudio -destination platform=macOS -derivedDataPath build build
```

Offline tests cover key validation/redacted descriptions, argument ordering, chapter escaping and fallback, metadata registration/reload, output collisions, conversion/validation failure, cancellation and staging cleanup. The optional real FFmpeg test generates unencrypted AAC in an MP4 container named `.aax` to exercise remuxing and chapter/tag preservation; it requires a full FFmpeg build with `lavfi` and an AAC encoder. A separate optional encrypted test uses `LECTERN_TEST_AAX` and `LECTERN_TEST_AAX_KEY`, converts the supplied file and rejects an incorrect key. This was run successfully against the public AAX sample linked by the [FFmpeg demuxer contributor](https://ffmpeg.org/pipermail/ffmpeg-devel/2015-July/175788.html). No user secrets or audiobook files are committed as fixtures.

The helper lives in `Contents/Helpers/ffmpeg` and is signed with exactly `app-sandbox` and `inherit` entitlements, following [Apple's helper-tool guidance](https://developer.apple.com/documentation/xcode/embedding-a-helper-tool-in-a-sandboxed-app). Selecting an external Homebrew executable is insufficient in the App Sandbox, as verified with a sandboxed probe. The app keeps its existing sandbox enabled. CI builds with `CODE_SIGNING_ALLOWED=NO` compile/package the helper but cannot validate signed runtime behavior.

Local verification: 17 tests passed with Xcode 27.1's toolchain targeting macOS 26, including public encrypted-AAX success/wrong-key rejection. The encrypted test also passed with the minimal FFmpeg 8.0 build. A signed sandbox probe converted the public sample in an external folder granted through `NSOpenPanel`; its output duration was 2985.900408 seconds. The signed app built successfully, its nested signatures verified, and the conversion sheet was rendered and visually inspected. Linux CI was not run locally.

For UI snapshots, `LECTERN_CONVERSION_PREVIEW=1` opens the conversion sheet for `LECTERN_SELECT` in debug builds, without reading Keychain or starting a conversion. It works with the existing `LECTERN_LIBRARY` and `LECTERN_SNAPSHOT` debug variables.
